## 2. Карта исправлений критических дефектов (Sprint 2.2.1 Verification & Integration)

1. **P0 MetaTools: Звуковые профили и NotificationChannels:**
   - *Было:* Параметр `sound` передавался, но воспроизведение звука и вибрации не имело специализированных каналов Android NotificationChannel.
   - *Исправлено:*
     - Созданы отдельные каналы уведомлений для звуковых профилей: `metaschool_alarm_school`, `metaschool_alarm_digital`, `metaschool_alarm_gentle`, `metaschool_alarm_default` с соответствующими атрибутами `AudioAttributes.USAGE_ALARM` и профильными паттернами вибрации (`NotificationHelper.kt`).
     - В `AlarmReceiver.kt` добавлена маршрутизация уведомлений в канал звукового профиля и дифференцированная вибрация.

2. **P0 MetaTools: Проверка результата планирования и честные статусы:**
   - *Было:* UI предполагал синхронный успех `scheduleNativeAlarm()` без разделения состояний ошибки, ожидания прав или локального режима.
   - *Исправлено:*
     - `scheduleNativeAlarm()` в `native.ts` возвращает структурированный `ScheduleAlarmResult` со статусами: `scheduled_android`, `saved_local`, `pending_permission`, `error`.
     - В `types.ts` и `Alarm` введено свойство `status: AlarmStatus` и `scheduleError`.
     - В интерфейсе `ToolsScreen` отображаются честные бейджи статуса для каждого будильника и баннеры предупреждения в случае отсутствия системного разрешения.

3. **P0 MetaTools: Валидация расписания и расчёт для всех 7 дней недели:**
   - *Было:* Не было строгой валидации формата времени `HH:mm` в UI и модуле `native.ts`. Не было автоматизированного теста для всех семи дней недели.
   - *Исправлено:*
     - Добавлены функции `isValidAlarmTime()` и `sanitizeAlarmDays()`.
     - Написан unit-тест #24, проверяющий валидацию формата, переход через полночь и расчёт следующего срабатывания для всех 7 дней недели (0..6).

4. **P1 Android Native Bridge: Единый контракт scheduleAlarm:**
   - *Было:* Устаревшая перегрузка `scheduleAlarm(alarmId, triggerAtMillis, title, message)` создавала будильник на жестко закодированные 07:30.
   - *Исправлено:*
     - Перегрузка обновлена: время извлекается из `triggerAtMillis` с форматированием в `HH:mm`, исключая фиктивные 07:30.
     - Добавлен возврат `Boolean` статуса выполнения.

5. **P1 MetaPersonal: Описание задач, повторение (daily/weekly/monthly) и редактирование товаров:**
   - *Было:* Поля `description` и `repeat` не были выведены в модальное окно создания/редактирования задач. Не было реального продвижения срока при завершении повторяющихся задач. В списках покупок не было редактирования позиций в UI.
   - *Исправлено:*
     - В `personal-screen.tsx` добавлены поля описания и выпадающий список повторения (ежедневно, еженедельно, ежемесячно).
     - В `store.ts` метод `togglePersonalTask()` при отметке выполнения повторяющейся задачи автоматически рассчитывает следующий срок (`due`) и сбрасывает подзадачи на новый цикл.
     - Добавлена кнопка редактирования товара в списках покупок и модальное окно редактирования с вызовом `updateShoppingItem()`.

6. **P1 MetaSync: Автоматическая миграция Zustand Persist v2:**
   - *Было:* Функция `migrateOutboxStates()` существовала автономно, но не была встроена в хук миграции `persist()`.
   - *Исправлено:*
     - Конфигурация персистенции в `store.ts` обновлена до версии 2 с хуком `migrate: (persistedState, version) => ...`, автоматически конвертирующим все устаревшие записи `delivered` в `local_synced` при гидратации хранилища.
