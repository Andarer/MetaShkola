## 1. НАЗНАЧЕНИЕ И ЦЕЛИ

MetaCommunity обеспечивает защищённую коммуникационную среду для всех участников образовательного и семейного процесса:
- **Школьные классы:** официальные объявления, домашние обсуждения, учебные вопросы.
- **Тематические клубы:** олимпиады, кружки, проекты.
- **Семейные советы:** закрытые семейные обсуждения, планы и списки.
- **Личные диалоги:** прямое общение между пользователями с гарантией приватности.

---

## 2. КЛИЕНТСКИЙ УРОВЕНЬ (ТЕКУЩЕЕ СОСТОЯНИЕ)

На клиенте MetaCommunity реализован на базе локального хранилища с ролевой изоляцией:
1. **Типы сущностей (`src/lib/ms/types.ts`):**
   - `CommunityPost`: публикации с категоризацией (`kind`: `announcement`, `question`, `achievement`, `general`), уровнями видимости (`class`, `school`, `family`, `only_me`), реакциями (`like`, `heart`, `light`, `grad`) и вложенными комментариями.
   - `CommunityGroup`: сообщества с типами (`class`, `club`, `family`), привязкой к пространствам и списками администраторов.
   - `CommunityReport`: жалобы на спам, буллинг или неприемлемый контент.
2. **Локальный RBAC (`src/lib/ms/rbac.ts`):**
   - Ученики видят только публикации своей школы и своего класса.
   - Родители имеют доступ к публикациям классов своих детей и семейным советам.
   - Чужие семейные советы и черновики изолированы от посторонних профилей.

## 3. СЕРВЕРНЫЙ ТРАНСПОРТ И КОНТРАКТЫ (ЦЕЛЕВАЯ АРХИТЕКТУРА)

### 3.1. Модель протокола
- **REST API (HTTPS):** Для аутентификации, загрузки истории, управления членством в группах и подачи жалоб.
- **WebSocket (WSS) / Server-Sent Events:** Для доставки новых сообщений, индикаторов набора текста и изменений реакций в реальном времени.

### 3.2. REST Endpoints

#### Аутентификация и сессии
- `POST /api/v1/auth/session` — обмен локального токена профиля на JWT сессии сообщества.
- `DELETE /api/v1/auth/session` — отзыв сессии.

#### Сообщества и группы
- `GET /api/v1/spaces/:spaceId/groups` — получение списка групп, доступных пользователю по его RBAC-ролям.
- `POST /api/v1/groups` — создание нового сообщества или клуба.
- `POST /api/v1/groups/:id/join` / `leave` — вступление и выход из открытых клубов.

#### Публикации и обсуждения
- `GET /api/v1/groups/:groupId/posts?limit=50&cursor=...` — получение ленты постов с постраничной навигацией.
- `POST /api/v1/groups/:groupId/posts` — создание публикации:
  ```json
  {
    "kind": "announcement",
    "title": "Подготовка к лабораторной",
    "content": "Текст объявления...",
    "visibility": "class",
    "tags": ["физика", "7А"]
  }
  ```
- `POST /api/v1/posts/:postId/reactions` — установка или снятие реакции (`type`: `like` | `heart` | `light` | `grad`).
- `POST /api/v1/posts/:postId/comments` — добавление комментария.

#### Безопасность и модерация
- `POST /api/v1/reports` — отправка жалобы модераторам школы:
  ```json
  {
    "targetType": "post",
    "targetId": "post-123",
    "reason": "Нарушение правил общения"
  }
  ```

## 4. ОФЛАЙН-СИНХРОНИЗАЦИЯ И РЕКОНСИЛЯЦИЯ (OFFLINE RECONCILIATION)

1. **Outbox Pattern:**
   Все действия пользователя (создание поста, комментарий, реакция) сохраняются сначала в локальный `outbox` со статусом `pending`.
2. **Локальный оптимистичный рендеринг:**
   UI отображает созданный контент немедленно с маркером локального сохранения.
3. **Отправка при наличии сети:**
   При появлении подключения фоновый синхронизатор передает операции на сервер.
   - При успешном принятии сервером статус становится `synced`.
   - Если сервер недоступен, фиксируется статус `local_synced` без ложных рапортов о доставке.
4. **Идемпотентность и дедупликация:**
   Каждое сообщение и операция снабжаются уникальным клиентским `uid()`. При повторной отправке сервер выполняет upsert, исключая дубликаты.

## 5. СКВОЗНОЕ ШИФРОВАНИЕ (E2EE) ДЛЯ ЛИЧНЫХ ДИАЛОГОВ

- Личные сообщения между двумя пользователями шифруются с использованием протокола **Double Ratchet** (или Signal Protocol).
- Сервер видит только зашифрованный конверт, отправителя, получателя и временную метку.
- Публичные каналы классов и клубов шифруются на транспортном уровне (TLS 1.3) с хранением в защищенной базе данных для обеспечения модерации учебного заведения.
